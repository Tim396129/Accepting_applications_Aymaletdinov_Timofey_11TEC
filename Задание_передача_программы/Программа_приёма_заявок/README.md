# Приём заявок на Python и Tkinter

В основу взят предоставленный преподавателем app_v03_для_тестирования.py. В комплекте он называется app.py. В исходной сборке 0.3.0 сохранено поведение счётчиков и кнопок. Удалены устаревшие комментарии «раскомментируйте», а путь к logo.png привязан к папке скрипта.

## Открыть в VS Code

Подробный маршрут с выделенными кнопками — в презентации 01 и PDF 03 в корне распакованного задания. PDF имеет кликабельное оглавление.

1. Полностью распакуйте архив Задание_передача_программы.zip.
2. В VS Code: File → Open Folder… → Задание_передача_программы/Программа_приёма_заявок.
3. В Explorer должны быть app.py, logo.png, README.md, ТРЕБОВАНИЯ.txt, ЗАПРОС_ЗАКАЗЧИКА.txt, УСЛОВИЯ_ЗАДАНИЯ.txt и папка После_исправления.
4. Документы создавайте в папке Передача_программы внутри этой папки. Пустые шаблоны находятся в Шаблоны рядом с программой.

## Запуск исходной 0.3.0

Нужен Python 3 с Tkinter. Сторонние библиотеки устанавливать не требуется.

1. В VS Code: Terminal → New Terminal (Терминал → Создать терминал).
2. Убедитесь, что терминал открыт в папке Программа_приёма_заявок.
3. Windows: python app.py. Если команда python не найдена, попробуйте py app.py.
4. Mac или Linux: python3 app.py.
5. Откроется окно «Приём заявок 0.3.0» с логотипом, количеством, датой, статусом и кнопками.

Если Python не найден, нужно выбрать или настроить интерпретатор Python на учебном компьютере. Если написано No module named tkinter, в выбранной установке нет Tkinter.

## Что проверять

Прочитайте ТРЕБОВАНИЯ.txt и запрос заказчика. Исходные данные здесь — нажатия и состояния окна, а не номера записей. Начните с 0, принимайте заявки до границы 10, проверяйте статус, дату и сброс. Для каждого теста фиксируйте версию, число нажатий, ожидание и увиденный факт.

## Повторная проверка в 0.3.1

1. Сначала зарегистрируйте дефект исходной программы.
2. Закройте её окно. В терминале основной папки выполните Windows: python После_исправления/app.py (или py После_исправления/app.py); Mac/Linux: python3 После_исправления/app.py.
3. Убедитесь, что в заголовке указана 0.3.1. Повторите исходный тест, затем прежние действия.

Для запуска исправленного app.py через другой способ его logo.png должен оставаться рядом.

## Комплект для передачи и возврата

Передавайте app.py и logo.png одной версии вместе с инструкцией и результатами тестов. Для возврата храните отдельную копию исходных app.py и logo.png. При закрытии окна текущие счётчики теряются: эта программа не хранит заявки на диске. Исправленная сборка тоже не добавляет сохранение.

## Учебное обращение

Создайте отдельную папку Копия_для_проверки. Скопируйте туда только исходный app.py, запустите его и запишите настоящую ошибку из терминала. Затем скопируйте в эту же папку logo.png и повторите запуск. Не удаляйте картинку из основного комплекта.

## Ограничения модели

Общий счётчик и общий статус. Нет списка отдельных заявок, поиска, файлов данных, базы данных, авторизации и многопользовательской работы. «Закрыто заявок» считает переходы общего статуса в «Готово»; повторный цикл может снова увеличить значение. Такой порядок сохранён из учебной программы, он не является учётом уникальных заявок.
